## 快速开始

1. 双击 **`启动.bat`**（浏览器会打开到 `http://127.0.0.1:8765`）
2. 左侧选「图片」→ 输入或浏览一个照片文件夹 → **添加** → **开始扫描**
3. 扫完自动出重复组；点「自动选择」按规则勾选，再「移到回收站」或「移到文件夹」

不用安装任何东西，运行时是程序目录里的 `runtime\`。关掉窗口就退出。

命令行参数（一般用不到）：

```
runtime\python.exe app.py --port 8765 --engine auto --load 100
                                 --data <数据目录> --no-browser
                                 --selfcheck [--json]      只打印环境自检
                                 --fill-patches            只补图片灰度指纹
```

## 从源码运行

需要 **Windows + Python 3.10 ~ 3.13**（实测 3.12）。

```bat
:: 1) 装依赖（建议用虚拟环境）
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

:: 2) 可选：GPU 加速
::    NVIDIA（图片查重能吃 nvJPEG）
.venv\Scripts\python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130
::    任意 DX12 显卡（视频特征加速，图片也能走 DirectML）
.venv\Scripts\python -m pip install onnxruntime-directml

:: 3) 启动
启动.bat
```

`启动.bat` 会自动找 `.venv`、`runtime\` 或系统 Python。

## 图片查重

### 怎么用

1. **添加文件夹**：可以陆续加多个，结果会累积对比；勾「含子文件夹」递归子目录
2. **开始扫描**：可随时暂停/继续。已分析过的图片记在库里，下次只算新的
3. **看结果**：每组一张卡片，标着「建议保留」和相似度；点缩略图看大图，点 `⤢` 打开对比窗口
4. **处理**：点「自动选择」按规则勾选 → 「移到回收站」或「移到文件夹」，也可以只导出清单
   * 文件多时**分批处理**（每批 40 个），每批完成立刻从列表里消失、统计跟着变，
     不用等全部处理完再看结果

筛选条上的几个词：

| 控件 | 含义 |
| --- | --- |
| **相似度阈值** | 感知哈希的汉明距离，数字越小越严格（默认 10，范围 2–20） |
| **排序** | 按可释放空间 / 重复张数 / 相似度 / 索引顺序 |
| **每组至少** | 少于这个张数的组不显示 |
| **范围** | 只看某个已扫描的文件夹 |
| **检索强度** | 快速 / 标准 / 彻底（分桶检索时的探测层数） |
| **占用** | 算力百分比，见[算力一节](#算力混合引擎与限速) |

### 怎么判重（三道关）

| 关卡 | 做法 | 作用 |
| --- | --- | --- |
| ① 感知哈希筛候选 | pHash + 裁边版 pHash，距离 ≤ 阈值 | 快，负责召回 |
| ② dHash 结构校验 | 梯度哈希距离 ≤ 16（pHash ≤ 4 时免检） | 挡掉"构图像但内容不同" |
| ③ 灰度指纹确认 | 每张图存 16×16 灰度指纹（256 字节），归一化相关系数 **≥ 0.96** 才算同图 | 真重复实测 ≥0.99，同人不同姿势只有 0.7–0.9 |
| ④ 星形聚类 | 每个成员只和**种子**（画质最好的那张）比较 | 簇直径 ≤ 2×阈值，不会 A~B~C 越滚越大 |

实测（6.8 万张真实图库）：

| 指标 | 早期版本 | 现在 |
| --- | --- | --- |
| 最大重复组 | 305 张 | **27 张** |
| ≥30 张的组 | 5 个 | **0 个** |
| ≥10 张的组 | 62 个 | **14 个** |
| 召回（pHash≤2 的真重复仍同组） | 99.9% | 98.4% |

> 觉得还不够严：阈值调到 6–8；觉得漏了：调到 12–14。

### 「其他文件」

工具栏右侧的 **其他文件 (N)** 列出没参与查重的文件：读不出来、后缀和内容不符、太小等。
每一项都有完整路径、原因、大小，可以「预览 / 系统程序 / 定位」。

### 大图库

| 规模 | 做法 | 实测 |
| --- | --- | --- |
| ≤ 12 万 | 分桶逐条查询（召回最好） | 6.8 万：**3.5 秒** |
| > 12 万 | 按宽高比分片 + 桶内整块矩阵 | 50 万：**4.7 秒**；100 万：**20 秒** |

同一批图换阈值不用重算候选（候选对带距离缓存），6.8 万张**0.3 秒**出结果。

## 视频查重

* 玩法：左侧「视频」→ 添加文件夹（或单个视频所在目录）→ 开始扫描
* 原理：均匀抽 8 帧 → MobileNetV2 画面特征（1280 维）→ 帧间最优匹配分
* 另加两道硬门槛：**时长相差 >3%** 直接不比；**首帧 pHash 差 >26 位** 直接不比
* 阈值默认 **0.88**；实测"完全不同"约 0.72–0.75，真重复 1.000，半重叠 0.86–0.87

**预览**：每行左边是首帧缩略图，中间一个 **▶**，点开就是播放器——能拖进度条（Range 流式传输）、
切同组成员、← → 翻页、ESC 关闭。编码浏览器放不了的（HEVC / MKV / rmvb）点「系统播放器」。

**其他文件**：小于 64 KB 的视频、视频目录里的 GIF 动图、没画面/损坏的文件都会进这里，
同样能看缩略图、预览、定位：

## 音频查重

* 原理：8 kHz 采样 + 频谱峰值指纹，取最相似的抽样窗口比对
* 阈值默认 **0.35**；实测无关音频 ≤0.05，同一首的不同响度 0.75–1.00，阈值落在空档里
* 可选「含视频里的音轨」：把视频文件的音轨也当音频来查
* 预览：行上的 ▶ 播放器（迷你播放条），同样支持同组切换
* **波形图**：预览弹窗上半部分是整段音频的波形（ffmpeg 解成 4 kHz 单声道后压成包络，
  自动归一化），一眼看出哪里是高潮、哪里是静音；**点一下/拖动波形可以跳转**，
  播放时有一条进度线跟着走。视频预览也会显示音轨的波形
* **按文件类型选播放器**：音频页里如果有带音轨的 mp4（勾了「含视频里的音轨」就会出现），
  点开用的是视频播放器 + 音轨波形，不会只放声音
* 组内成员超过 12 个时，切换条只显示 12 个 + 「还有 N 个」，用「上一个 / 下一个」翻，
  不会把播放器挤出去
* 放不出来时会说清原因：**文件不存在** / **程序还是旧版本**（预览接口没加载）/ **编码浏览器不支持**（用「系统播放器」）

## 小说查重

* 按**书名相似度**（默认 0.82）+ 章节数分组，再算正文重合标出"正文重复"
* 扫描时解析章节（txt / epub / docx / html / md / rtf / pdf），10 万字约几十毫秒
* 星形聚类：每个成员必须直接和代表的书名够像，避免"系列名相似"被串成一大组
  （实测 2,900 本：最大组 38→16 本，组内不再出现低于阈值的成员）

## 打包 / 解压

### 打包（流程可编辑）

页面 = 输入/输出 + 一个**步骤列表**，按顺序执行，中间产物都在内存里，最后才写盘：

| 步骤 | 能配什么 |
| --- | --- |
| 压缩 | 格式（zip / 7z）、加密（ZipCrypto / AES-256）、密码、压缩级别、是否每个文件单独打 |
| 合并再压一次 | 用自己的格式/密码再打一层 |
| 拆分 | 按份数或按大小切卷，可限定最小/最大卷数或卷大小 |
| 改输出名 | 自定义文件名模板 |
| 拍平嵌套 | 去掉多余目录层级 |

* zip 走多线程 zlib（文本约 177 MB/s，16 线程）；jpg/png 这类已压缩的直接存储（STORE）
* 7z 调 `vendor\7z\7za.exe`
* 中文名自动打 UTF-8 标记；支持中文密码

### 解压

* 多层/分卷在内存里逐层解开，只写最终文件（`.z01`、`.001` 分卷自动合并）
* 支持 zip（含 AES）、7z、tar/gz/bz2/xz；RAR 需要本机有 WinRAR 或完整版 7-Zip
* 带**密码本**：可以用「已破解密码」里的记录，也可以选外部字典，逐层试
* 乱码文件名会尝试修复（cp437 → 中文）

* **繁简编码**：繁体转简体、任意编码转 UTF-8 / GBK / BIG5 / UTF-16，可改换行；支持粘贴一段文字试算并复制结果

## 暴力破解

* 支持 zip（ZipCrypto / AES）、7z、PDF、Office 2007+；RAR 靠 WinRAR 或 7-Zip 逐个试
* 模式：智能（先试密码本，再按位数穷举）/ 只字典 / 只数字 / 按字符集
* 字典支持**变形**：大小写、字母换数字（a→@）、末尾加数字；也支持前后缀
* 开始前会算"要试多少组合、大概多久"
* NVIDIA 显卡走 hashcat（`vendor\hashcat-8.0.0`）；没有就 CPU 校验
* 实测（RTX 5080）：AES zip ≈12 MH/s，ZipCrypto ≈40–120 MH/s，7z ≈1.57 MH/s，PDF R5 ≈750k/s/核

## 存档

存档 = 把当前扫描结果（路径 / 哈希 / 尺寸 / 文件夹列表）存成一个 JSON，下次直接接着用，不用重扫。

弹窗分两步：

1. **保存当前结果**：上面一行是"现在有什么"（多少张图、多少组、预计多大），填名字点保存
   （同名不会互相覆盖，会自动加「（2）」）
2. **我的存档**：每个存档一行，写着数量、大小、保存时间，右边五个按钮
   **载入**（替换当前结果）· **合并**（并进当前结果）· **覆盖**（用当前结果重写）· **导出**（另存 .json）· **删除**

细节：

* 存档**不含图片本身，也不含缩略图和灰度指纹**（6.8 万张约 30 MB）；载入后后台自动补指纹
* 存档在 `data\archives\`，图片和媒体分开放，互不影响
* 可以「导入存档文件…」把别人给的 `.json` 导进来

## 算力：混合引擎与限速

### CPU + 显卡混合（默认）

JPEG 交给显卡（nvJPEG），PNG/WebP 交给 CPU 线程池，两边从**同一个队列**取活（work stealing），
快的自然拿得多。实测 300 张真实照片：纯 CPU 193 张/秒、纯 GPU 135 张/秒、**混合 237 张/秒**。

引擎是 `auto` 时每次扫描会现场对比一次再决定；也可以在设置里固定 CPU / GPU。

### 占用百分比（降噪）

工具栏「占用」下拉，或设置里的同名项：

| 占用 | 实测吞吐 | 体感 |
| --- | --- | --- |
| 100% | 237 张/秒 | 满速，风扇会响 |
| 80% | 189 张/秒 | 轻微降噪 |
| 60% | 135 张/秒 | 风扇基本听不见 |
| 40% | 96 张/秒 | 办公时挂后台 |
| 20% | 50 张/秒 | 几乎无感 |

CPU 侧按比例减线程数，显卡侧按"干多久歇多久"限速。改设置**下次扫描生效**。

### 重新测速

```
runtime\python.exe bench.py --write
```

依次测 CPU 不同线程数、GPU、混合，把推荐值写进 `settings.json`。

## 显卡支持与便携使用

### 各家显卡能用到什么

| 显卡 | 图片查重 | 视频/音频查重 |
| --- | --- | --- |
| **NVIDIA**（驱动支持 CUDA） | 显卡（CUDA：nvJPEG + 显存里算哈希） | 显卡（DirectML） |
| **AMD / Intel**（装了 torch-directml） | 显卡（**DirectML** 备用方案） | 显卡（DirectML） |
| **AMD / Intel**（没装 DML） | CPU（多线程，自动选线程数） | **显卡（DirectML）** |
| 没有独显 / 核显很弱 | CPU | CPU |
| 完全没装 torch | CPU | 显卡或 CPU |

* 选路顺序是 **CUDA → DirectML → CPU**，`--selfcheck` 会打出"加速能力"一行
* 图片哈希是"解码 + 缩放 + DCT"：NVIDIA 能用 nvJPEG 解码，真正吃到显卡；
  DirectML 没有 nvJPEG（解码仍在 CPU），所以主要加速后半段的缩放/DCT，
  是否真的更快由 `auto` 模式现场测速决定（快 5% 以上才会选 GPU）
* 视频特征用的是 ONNX Runtime 的 **DirectML**，NVIDIA / AMD / Intel 都能加速

### 给非 NVIDIA 显卡开图片加速（DirectML）

DirectML 版 PyTorch 和 CUDA 版装不到同一个运行时里（会互相替换），所以做成**备用方案**：

```
双击「安装 DirectML 加速.bat」
```

脚本会提示"这会把 CUDA 版换成 CPU+DML 版"，确认后执行 `pip install torch-directml`，
装完自动跑一次自检。之后：

* 图片查重会尝试 DirectML 路径，`auto` 模式实测不比 CPU 快就仍然用 CPU
* 想换回 CUDA：`runtime\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130`
* 只是想在别的电脑上试试、又不想动当前运行时：把装了 DML 的 Python 路径写进 `gpu_python.txt`

### 换电脑 / 换目录

整个文件夹拷走即可（含 `runtime\`、`vendor\`、`data\`）。换机器后：

```
启动.bat                       正常启动
runtime\python.exe app.py --selfcheck
```

自检会告诉你：内置运行时是否生效、torch/CUDA 是否可用、ffmpeg/模型是否齐全、
图片格式支持多少种、数据目录能不能写。

注意：

* **不要放在 `C:\Program Files` 这类需要管理员权限的目录**（`data\` 写不进去）
* 路径里有空格、中文都没问题（已实测：路径含空格、中文都能正常跑）
* 换到没有 NVIDIA 的电脑时，torch 仍能导入，只是自动退回 CPU；启动慢 1–2 秒属正常
* 想让那台机器也有 GPU 图片加速：装对应 CUDA 版本的 torch（见 [`AGENT_SETUP.md`](AGENT_SETUP.md)）

| 组成 | 大小 | 说明 |

## 常见问题

**Q：还没开始扫描，为什么占 CPU？**
不会了。灰度指纹改成「第一次看分组时才补」，4 线程 + 限速，左侧会显示进度；启动后空闲时 CPU 应为 0%。

**Q：扫描结果里点视频只出现一堆文件名，没有播放器？**
那是服务端还是旧代码。关掉黑窗口重新双击 `启动.bat`（后端改动需要重启，界面是自动刷新的）。

**Q：点「覆盖」存档失败 / `data\archives` 里有几百字节的 `.tmp`？**
早期版本会把二进制字段导进存档，写到一半就报错。现在导出只取存档字段，写失败会清掉 `.tmp`。

**Q：完全不同的图片被分到一组？**
老版本用连通分量会"链式合并"。现在星形聚类 + 灰度指纹确认，实测最大组 305 → 27 张。

**Q：某些照片没被扫到？**
点工具栏的「其他文件 (N)」，里面列出读不出来 / 后缀不符 / 太小的文件及原因。

**Q：能查 NAS / 网络盘吗？**
能，按普通路径处理，但速度受网络限制；建议先本地扫完再用存档合并。
